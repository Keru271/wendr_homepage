📚 Developer REST API Specification

Developer Storefront API Documentation

Complete technical reference for building on top of OmniStore. All endpoints run on port 5002 under the prefix /api/v1, authenticated via your public storefront key.

🚀 Quick Start & Base URL

Every store deployed on the platform exposes the Developer API. In local development, the API listens on port 5002. In production, requests are routed through your store's custom domain or platform subdomain.

Base Endpoint URL
http://localhost:5002/api/v1

Self-Describing API Root

Send a GET request to /api/v1/ with your key to retrieve the live directory of available endpoints and API metadata:

GET /api/v1/ • 200 OK 
{
  "name": "Shoppify Developer API",
  "version": "v1",
  "base_url": "/api/v1",
  "authentication": {
    "storefront_key": "Pass your Storefront API key in X-Storefront-Key header (pk_live_xxx)",
    "customer_token": "For customer-specific endpoints, pass: Authorization: Bearer <customer_token>"
  }
}

🔐 API Authentication

Authentication ensures requests are routed to the appropriate store tenant and that rate limits are enforced. The Developer API utilizes two distinct authentication tiers:

Auth Type Header Name Example Value Applies To
Public Storefront Key X-Storefront-Key pk_live_9a8b7c6d5e4f3a2b1c... Every Request (Store, Products, Collections, Cart, Checkout)
Customer Session Token Authorization Bearer eyJhbGciOiJIUzI1... Customer authenticated endpoints (/customers/me)
Security Guarantee: pk_live_... keys are strictly scoped to public-facing storefront endpoints. They cannot perform administrative store updates, delete orders, view merchant bank payouts, or modify merchant credentials.
💳 Plan Requirement: API Tier Add-on (1,000/month)

The API Tier (1,000/month) is an independent add-on dedicated strictly to Developer API access. Subscribing to it unlocks the complete Developer Storefront API (/api/v1/*), API key creation, and Webhooks without altering your current base tier (e.g. your store remains on Free Starter, Basic, or Growth). Stores without the API Tier add-on receive HTTP 403 Forbidden with code API_TIER_REQUIRED. You can activate the API Tier anytime in Dashboard → Billing.

🛒 End-to-End Integration Walkthrough

Here is how to implement a complete, headless shopping journey from product discovery to payment capture:

1
Create an Empty Cart: Call POST /api/v1/cart. Store the returned cart_id in the user's browser (e.g. localStorage).
2
Add Items to Cart: Call POST /api/v1/cart/:id/items with product_id, variant_id (if applicable), and quantity. Real-time inventory is verified.
3
Initiate Checkout Session: Call POST /api/v1/checkout with cart_id, customer email/name, and shipping address. The system computes subtotal, taxes, shipping, coupon discounts, and returns live payment gateway identifiers (Razorpay Order ID, Stripe Publishable Key).
4
Capture Payment & Listen for Webhook: Initialize Razorpay.js or Stripe Elements using the returned IDs. When payment captures, your backend receives a signed checkout.completed webhook!

⚠️ Error Handling Matrix

All error responses return a standardized JSON envelope with an error category and a descriptive message: 

{
  "error": "Out of Stock",
  "message": "Only 1 unit(s) of \"AeroPulse Headphones\" are available."
}
Status Code Error Category Typical Cause Resolution Guide
400 Bad Request Bad Request / Out of Stock Missing required fields, requested quantity exceeds stock, cart is empty. Inspect message field. Adjust quantity or supply required parameters.
401 Unauthorized Unauthorized Missing or malformed X-Storefront-Key, or expired customer token. Ensure key begins with pk_live_ or pk_test_. Re-authenticate customer.
403 Forbidden Forbidden Enterprise plan upgrade required, or customer JWT used for admin task. Check store plan in Merchant Admin > Pricing & Billing.
404 Not Found Not Found Product ID, category slug, or cart token does not exist. Verify slug or ID against /api/v1/products or /api/v1/collections.
409 Conflict Conflict Customer email address already registered. Prompt user to login via POST /api/v1/customers/login instead.
500 Server Error Internal Server Error Database connectivity interruption or unhandled exception. Implement exponential backoff retry. Contact technical support if persistent.

POST /api/v1/payments/simulate X-Storefront-Key developer.sandbox

Developer Sandbox Simulator. Allows developers to test payment failure handling, decline logic, card authorizations, and webhook payload parsing without live payment credentials.

Scenarios Supported

  • SUCCESS: Returns authorized transaction ID, authorization code, and mock payment.completed webhook payload.
  • INSUFFICIENT_FUNDS: Returns HTTP 402 with insufficient_funds decline code.
  • CARD_DECLINED: Returns HTTP 402 with generic card issuer decline.
  • GATEWAY_TIMEOUT: Returns HTTP 504 with upstream gateway timeout simulation.

Event IdentifierGroupDescription & Trigger
checkout.completed Order Customer completes checkout session; payment captured.
payment.completed Payment Gateway transaction verified and confirmed.
order.confirmed Order Merchant confirms the order for fulfillment.
order.shipped Logistics Tracking number and courier carrier assigned.
order.delivered Logistics Courier marks package as delivered to customer.
product.updated Catalog Product title, media, or pricing changed — sync cache.
inventory.updated Catalog Inventory stock count decremented or replenished.
