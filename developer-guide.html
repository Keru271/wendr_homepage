Building Enterprise Integrations: REST APIs, Webhooks & Custom Runtimes

Author: Platform Engineering • Spec: API v1.4 • Read Time: 8 MIN

01 // API Authentication & Secret Key Generation

OmniStore CMS provides a high-throughput REST API for headless e-commerce, custom mobile apps, and ERP system synchronization. Every request to the OmniStore Developer API must include your secret API key in the HTTP Authorization header using the Bearer token scheme.

To generate an API secret key:

  1. Log into the Master Admin Control Panel (http://localhost:3000).
  2. Navigate to the Developer API tab in the sidebar menu.
  3. Click Generate Secret Key, specify your name identifier (e.g. ERP Sync Service), and select your scope permissions (e.g. read_products,write_orders).
  4. Copy your secret API token prefixed with sk_live_....
HTTP Authorization Header Bearer Authentication 
Authorization: Bearer sk_live_9f8a2b3c4d5e6f7a8b9c0d

02 // Core REST API Endpoints & Payloads

Interact with catalog products, submit orders, and query customer profiles directly via REST API endpoints.

GET /api/v1/products

Retrieves a list of catalog products with variant pricing, stock counts, and WebP media CDN URLs.

Bash / cURL HTTP Request 
curl -X GET "https://api.omnistore.internal/api/v1/products?limit=10" \
  -H "Authorization: Bearer sk_live_9f8a2b3c4d5e6f7a8b9c0d" \
  -H "Content-Type: application/json"
POST /api/v1/orders

Programmatically place customer orders and trigger automated multi-channel notifications (Email, SMS, WhatsApp).

03 // Real-Time Webhooks & HMAC Verification

Webhooks allow your application to receive real-time HTTP POST notifications when events occur in your OmniStore account (such as order.created, order.fulfilled, or product.updated).

Verifying Webhook Signatures (HMAC SHA-256)

To verify that incoming webhook notifications originated from OmniStore CMS and were not tampered with, compute an HMAC SHA-256 digest using your endpoint signing secret (whsec_...) and compare it against the X-OmniStore-Signature header.

Node.js / Express Signature Verification Handler 
const crypto = require('crypto');

function verifyOmniStoreWebhook(rawBody, signatureHeader, secret) {
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(rawBody, 'utf8')
    .digest('hex');

  return crypto.timingSafeEqual(
    Buffer.from(signatureHeader),
    Buffer.from(expectedSignature)
  );
}

04 // Custom Headless Runtimes & CSS Overrides

Merchants can inject tracking scripts (Google Tag Manager, Meta Pixel, PostHog) and custom CSS stylesheets directly into their storefront templates without modifying source files.

LOCATION IN MASTER ADMIN:
Navigate to Developer API > Custom Scripts / Custom CSS to edit scripts and stylesheet overrides in real time.

05 // Multi-Tenant RBAC & Permission Scoping

OmniStore CMS enforces role-based access controls across 5 staff tiers (Owner, Admin, Manager, Editor, Support) and 7 explicit feature matrix toggles (Products, Orders, Customers, Themes, Settings, Payments, Analytics).

When making API requests with staff tokens, permissions are evaluated atomically to ensure users cannot access restricted resources (e.g. Managers cannot view payment secrets or modify store billing).
